## 📢 版本概述

本次更新集中修复管理台会话、上游凭据摘要、更新下载和部署脚本的安全与兼容问题。同源 Web 管理台改用 HttpOnly 刷新 Cookie 与内存 Access Token；凭据相等比较升级为带版本、域分离的 HMAC。包含数据库迁移，升级前必须备份数据库、配置和原加密密钥，停止旧实例后统一升级。

## 🔧 改进与优化

- **浏览器会话**：同源登录、2FA、OAuth 和 Passkey 接入 Cookie 会话，页面重载可恢复短期访问令牌，跨标签页刷新协调不在 localStorage 中共享新令牌。独立跨源 Web 会话的新令牌只驻留页面内存，重载后需重新登录。
- **凭据一致性**：旧 SHA 摘要保留双读兼容，启动分批回填带 CAS 守卫；账号部分更新、探测快照和 Ollama 组身份比较同时适配版本化摘要。
- **实验桌面端**：存储不可用时更新设置回退默认值，避免重复触发安装及卸载后的异步资源残留。该目录仍不属于正式安装包或签名更新发布渠道。

## 🐛 问题修复

- **更新失败或错误匹配**：精确匹配平台归档，拒绝将签名、校验旁文件选为安装包；缺少 `checksums.txt` 或发行附件时明确失败。
- **Windows 二进制更新**：明确拒绝运行中原地替换和回退，保留版本发现与更新提示，使用停止服务后手动替换的方式升级。
- **会话兼容**：修复令牌刷新后继续使用旧内存值、SSE 与支付等功能绕过共享会话访问器，以及本地清理 CSRF Cookie 后无法再次登录的问题；密码和 Passkey 登录在缓存故障降级时统一清理旧刷新 Cookie。
- **数据库迁移回退**：阻止新版更新服务跨 v0.5.7 边界直接安装旧二进制；部署脚本在跨边界升级失败后保留备份并停止服务，避免自动运行不兼容的旧版。
- **Docker 配置**：升级保留原密钥及数据库密码，补全缺失或空值配置，首次安装不再保留示例数据库密码；固定的版本镜像设置能正确写入旧配置。
- **构建和审计 URL**：部署 Dockerfile 复制依赖覆盖与补丁所需文件；审计节点拒绝查询串、片段等不符合 API 基址约定的 URL。

## 🔒 安全与兼容性

- **会话防护**：同源刷新令牌为 HttpOnly，HTTPS 下为 Secure，SameSite=Lax；写入请求执行精确 Origin 校验，刷新和登出使用绑定会话的签名双提交 CSRF。新 Web 会话不再将访问或刷新令牌写入 localStorage，旧值仅用于迁移读取。旧版 Bearer、CLI 和桌面 API 协议保持兼容；独立跨源 Web 采用内存会话，建议通过同源反向代理启用持久 Cookie 模式。
- **凭据指纹**：新增 `credentials_digest_version`，新写入使用 HMAC-SHA-256；启用字段加密时从外部加密密钥独立派生摘要密钥。未启用字段加密的部署仍会明文保存凭据，不能因此宣称已抵御完整数据库泄漏。
- **配置失败关闭**：缺少凭据加密器或配置的公开仓储构造不再退回旧 SHA 写入路径；密钥错误、解密失败及并发更新分别由阻断、保留原值和 CAS 守卫处理。
- **下载边界**：GitHub 更新下载只接受精确可信 HTTPS 主机，重定向逐跳检查并保留跳数上限，校验文件有大小上限。
- **响应边界**：流式及 JSON 保活响应显式禁止 MIME 嗅探，并保留敏感错误日志脱敏回归测试。

## 🔄 升级与数据迁移

- **升级前**：备份数据库、配置以及原 `TOTP_ENCRYPTION_KEY`，停止所有旧服务端实例，再统一升级。使用本版部署脚本或停机手动替换，旧版更新器无法执行新的迁移保护。迁移 207 自动添加摘要版本列，启动时严格解密并分批 CAS 回填；无法解密的行保留原值并告警，需要恢复正确密钥或重新录入凭据。
- **兼容性**：支持读取旧摘要和旧 Bearer 客户端，但不支持新旧服务端同时连接同一数据库。首次加载更新后的 Web 管理台时会迁移旧会话；同源会话进入 Cookie 模式，独立跨源管理台重载页面后需要重新登录。
- **配置和数据**：现有数据与密钥保留，本版不自动轮换加密密钥。多实例必须使用相同配置与密钥；不要在本次升级中同时更换加密密钥。
- **回退方式**：回退到 v0.5.6 或更早版本必须恢复升级前的数据库、配置与二进制。新 HMAC 摘要不被旧版理解，仅替换二进制或脚本健康失败自动换回旧文件并不足以完成数据回退。
- **脚本确认**：使用本版 `deploy/update-binary.sh` 跨迁移升级时，完成备份并停止旧实例后设置 `SUB3API_DATABASE_BACKUP_CONFIRMED=1`。若启动或健康检查失败，服务保持停止；恢复升级前数据库、配置及二进制后再启动。

## ⚠️ 已知问题

- 未配置外部 `TOTP_ENCRYPTION_KEY` 时，上游凭据仍按既有边界明文保存。
- 独立跨源 Web 会话仅在当前页面有效，重载需要重新登录；未升级的旧版客户端仍保留其原有会话存储边界。
- 需要真实身份源、生产数据或独立设备的验收不由单元测试替代；FreeBSD 和非原生构建目标没有在本地真机运行。
