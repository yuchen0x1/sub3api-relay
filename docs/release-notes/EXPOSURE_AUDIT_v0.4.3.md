# v0.4.3 发布产物静态审计

日期：2026-11-13。此为 v0.4.3 发布准备阶段的静态记录（该版随后取消发布）。v0.4.4 使用本机 Go 1.26.11 重新构建并复扫，规则命中集合与 Web 无命中结论相同；可达漏洞检查通过。对象为本仓库的嵌入式 Web 构建与本地 Windows amd64 发行参数构建；其他平台由发布工作流构建，本报告不替代其运行验收。

## 1. 总览

- Web：扫描 170 个文件、122 个 Web 资源，扫描器评分 100/A，未命中规则。
- Windows：扫描 1 个二进制，原始评分 14/D。该分数包含通用字符串误报，不作为应用安全评级；修复前后的原始评分相同，不能据此判断剥离符号无效。
- 人工核对：确认未签名与未设置 PE CFG 标志；其余凭据、内网、用户名、授权标志字符串命中未证实为泄露。完整 PEM 私钥块匹配数为 0。
- 构建符号表从 142,923 条降为 0，文件从 168,138,752 字节降至 127,294,464 字节。比较对象分别为本轮未剥离的开发构建和发行参数构建，版本不同，不是性能基准。

## 3. 逐项证据与修复

- Windows 产物的 PE Security Directory 为空。后续如需操作系统发布者验证，应建立独立保管证书的签名流程；本次未创建证书或声称已签名。
- `backend/internal/service/update_service.go` 使用发布归档及 SHA-256 清单。独立认证需要为更新清单签名，并在客户端固化受信公钥和拒绝无效签名；仅追加一个散列文件不能实现这一目标。
- PE `DllCharacteristics=0x8160`，缺少 `0x4000` CFG 位。不得将 MSVC 的 `/guard:cf` 直接传给 Go 链接器；需要先确认 Go 工具链对目标平台的支持。
- `.github/workflows/release.yml` 加入 `-trimpath -ldflags="-s -w ..."`。发行参数构建的 PE 符号数量为 0，调试节已移除；Go 运行时仍可包含必要的函数名，源码本来就是公开的。
- `backend/internal/pkg/antigravity/oauth.go`、`backend/internal/pkg/xai/oauth.go` 明确使用 localhost 回调。它们不是组织内部服务器地址。
- 扫描器命中的 `/home/dist`、`/home/README.md`、`/home/sub3api.html` 对应前端资源路径语义，未发现本机用户目录；`entitlement` 对应上游配额字段。完整 PEM 块检查未发现可用私钥。
- `.dockerignore` 排除本地测试产物、缓存和浏览器登录态目录，避免它们进入构建上下文。

## 4. 客户端无法解决的问题

本项目为开源自托管服务，隐藏公开算法不是安全目标。Web UI 不是授权边界：备份路由通过服务端管理员鉴权，创建、恢复和 S3 配置修改入口另有二次验证，S3 凭据留在服务端配置中。此结论限定于本轮检查的备份路径，不是对所有接口的完整授权审计。

密钥加密依赖服务端固定的 `TOTP_ENCRYPTION_KEY`；同时控制配置与数据库的攻击者仍可能取得凭据。前端混淆无法保护已经泄露的服务端密钥，也无法解决发布账号失陷。没有为提高逆向成本而增加反调试或 JS 混淆。

## 5. 修复顺序

- P0：本次未确认硬编码的真实私钥或数据库密码，不进行无证据的密钥轮换。
- P1：发行参数剥离符号、移除构建路径、扩大校验清单覆盖范围、排除本地产物已落实；独立更新签名和 Windows 签名仍未实现。
- P2：保留服务器权限隔离和发布账号保护；各平台运行安全、真实升级和生产恢复应分别验收。本静态报告不证明这些流程通过。
