# Sub3API AI 自动部署指南

这份文档提供一段可以直接交给部署 AI 的提示词。它适用于你自己的服务器，也适用于为其他人配置一台全新的 Linux 服务器。

## 使用前准备

请准备以下信息：

- 服务器公网 IP 或主机名
- SSH 用户名
- 一次性 SSH 密码或临时私钥
- 已解析到服务器的域名
- 站长登录邮箱或用户名
- 首次登录要使用的站长密码

不要把真实密码、私钥、数据库备份或 API Key 写入公开仓库、聊天记录或提示词模板。部署完成后应立即撤销临时凭据并修改 SSH 密码。

## 可复制给 AI 的完整提示词

将下面的提示词复制给具备 SSH 操作能力的部署 AI，然后把尖括号内容替换成真实信息：

~~~text
你是 Sub3API 的服务器部署工程师。请只操作我明确授权的服务器，不要访问其他服务器。

目标项目：
- 仓库：https://github.com/yuchen0x1/sub3api-relay
- 部署优先使用官方 GitHub Release 或仓库 deploy/docker-compose.local.yml
- 产品名称统一使用 Sub3API，不要在用户可见文案中使用上游项目名称

服务器信息：
- 域名：<DOMAIN>
- IP：<SERVER_IP>
- SSH 用户：<SSH_USER>
- 临时 SSH 密码或私钥：<TEMP_CREDENTIAL>

请按以下顺序执行：
1. 先检查系统版本、CPU 架构、磁盘空间、DNS 解析、Docker/Compose 版本、已占用端口和防火墙状态。
2. 不要删除现有数据，不要触碰未授权的服务。若发现端口或目录冲突，先报告并停止。
3. 使用当前稳定 Release；若没有 Release，才使用仓库 Compose 文件。禁止从上游旧项目镜像拉取。
4. 创建独立部署目录。复制 deploy/.env.example 为 .env，设置随机 JWT_SECRET、POSTGRES_PASSWORD、TOTP_ENCRYPTION_KEY。首次启动完成基础设施准备后，访问 `/setup` 由站长设置唯一管理员账号和强密码；新部署不会生成 admin/admin。
5. 启动 PostgreSQL、Redis 和 Sub3API，设置自动重启，并等待健康检查通过。
6. 配置 Caddy 或 Nginx，将 <DOMAIN> 的 HTTPS 流量转发到本机 Sub3API。只公开 80/443，数据库和 Redis 不得暴露到公网。
7. 配置证书自动续期、防火墙、日志轮转、每日数据备份和备份保留策略。
8. 验证 HTTPS 首页、站长登录、/health、API Key 页面、使用记录、操作日志和一次最小 API 请求。
9. 检查服务重启后仍能自动恢复，检查证书续期任务和备份文件权限。
10. 输出部署摘要：域名、服务状态、监听端口、备份位置、健康检查结果和回滚命令。不要输出任何密码、私钥、Token、.env 内容或数据库内容。
11. 部署结束后提醒我立即修改临时 SSH 密码；不要自行把密码写入仓库或日志。

安全约束：
- 不上传 .env、backend/config.yaml、数据库、日志、备份、证书私钥或个人数据。
- 不执行 rm -rf、格式化磁盘、重置防火墙或删除容器，除非我明确确认具体路径。
- 不把服务器密码放入命令历史、Git、公开 issue、Release 或聊天输出。
- 如果任何检查失败，保留现场、收集脱敏日志并报告，不要强行继续。
~~~

## 部署后检查清单

- [ ] 已在 `/setup` 设置唯一站长账号和强密码
- [ ] 域名 HTTPS 正常，证书自动续期已验证
- [ ] 仅 80/443 对公网开放
- [ ] PostgreSQL、Redis 只在内网或 Compose 网络可访问
- [ ] 数据、日志和备份目录权限正确
- [ ] 自动重启、备份、健康检查都通过
- [ ] 临时 SSH 密码已更换或临时密钥已撤销

## 手动回滚

升级前先备份部署目录和数据库。Docker 部署可以恢复上一版本镜像并执行 docker compose up -d；发行版部署可以在侧边栏版本号下方打开版本回滚面板，选择目标版本后重启服务。
